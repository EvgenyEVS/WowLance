{% comment %} Конфигуратор функциональной команды и юнит-экономика проекта (Issue #11). Единственный источник разметки конфигуратора. Partial отдаётся двумя способами: внутри вкладки «Обзор» и ответом на HTMX-POST, который заменяет корневой div целиком по id. Поэтому здесь нет ни шапки комнаты, ни навигации по вкладкам — иначе обновление вложило бы страницу в саму себя. Ни одной цифры экономики шаблон не считает и ни одного названия функции не дублирует: и то и другое приходит из серверного context (`apps.rooms.configurator.build_configurator_context`) поверх сохранённого снапшота проекта. Ни `data-*` с ценой, ни расчёта в JS здесь нет и быть не должно: клиент выбирает только состав. Редактирование целиком управляется одним флагом `can_edit_functional_roles` (владелец + директор + статус DRAFT/STAFFING). Флаг решает только что видно; настоящая защита — те же проверки внутри `update_project_functional_roles`, поэтому прямой POST мимо интерфейса ничего не даст. {% endcomment %} {% url 'rooms:room_functional_roles_update' project.id as fr_update_url %} {% url 'rooms:room_functional_roles_apply_package' project.id as fr_package_url %}
