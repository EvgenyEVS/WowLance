1. Зачем

Модалка расторжения перекрывает весь экран, включая шапку сайта. Фрилансер с несколькими комнатами выходит только кнопкой «назад» в браузере. Протест — пустая кнопка: саппорт и тимлид не видят, с чем человек не согласен. Тимлид узнаёт «покинул / опротестовал», только если сам откроет форму.

Нужно: в этой комнате работать нельзя, из аккаунта выйти можно, в списке комната с открытым кейсом видна и помечена, протест письменный, исход виден в том же чате расторжения.

---

2. Что сделать

2.1. Шапка сайта поверх оверлея

Окно блокировки не должно перекрывать шапку сайта (логотип, Дашборд, Комнаты, Профиль, Выйти). Оверлей — на контент комнаты. Крестика «закрыл и работаю в этой комнате» по-прежнему нет: вкладки и кнопки этой комнаты за оверлеем не кликаются.

2.2. Кнопка «К списку комнат»

В модалке (и notice_sent, и appeal_pending) ссылка с точной подписью «К списку комнат» на список комнат фрилансера. Показывать всегда, даже если комната одна: нужны дашборд и профиль. Это выход из оверлея, не отзыв кейса и не «Покинуть проект».

2.3. Рабочий список: красная пометка + бейдж

Пока кейс notice_sent или appeal_pending, комната остаётся в рабочем списке «Комнаты», не в архиве.

У фрилансера эта строка визуально выделена (красный акцент: фон или полоска, не «вся таблица красная как удаление»).

Бейдж — ещё и вход в комнату (ведёт на Обзор этой комнаты, там та же модалка). Тексты точные:

- notice_sent: «Идёт расторжение — нужен ответ»
- appeal_pending: «Заблокировано, рассматривается увольнение»

Обычная «Открыть» тоже ведёт в комнату с модалкой. Архивная секция и спокойный стиль архива не менять.

Тимлид и директор в своём списке проектов эту красную пометку не получают: это сигнал исполнителя.

2.4. Системные сообщения в чат расторжения

Не командный чат и не DT. Не письмо тимлиду.

Два события, точные формулировки системных строк:

- «Покинуть проект» → «Фрилансер покинул проект»
- «Опротестовать» → «Фрилансер опротестовал расторжение» и следом текст из формы протеста (см. 2.5)

Системная строка при уходе пишется до закрытия кейса: после completed тред новые сообщения не принимает, и тимлид ничего не увидит.

Сообщения без «живого» автора (системные): в ленте не подписывать именем фрилансера как ручной чат. XSS: текст протеста экранировать, без safe.

Авто-уход по дедлайну (молчание = покинуть) — та же системная строка «Фрилансер покинул проект», тем же порядком.

Отзыв тимлида: можно одну системную строку «Увольнение отозвано» до закрытия треда; если уже есть такое при revoke — не дублировать.

2.5. Форма протеста

Кнопка «Опротестовать решение» без текста больше не отправляет протест.

Поле: обязательный текст, минимум 20 символов (как причина тимлида). Вложений нет.

Сохранить на кейсе (например appeal_reason). После отправки не редактировать. Показать только чтением: форма тимлида, Django admin, письмо на SUPPORT_EMAIL (тема/тело как сейчас плюс блок «С чем не согласен фрилансер»).

Пустой или короткий POST — 400, статус остаётся notice_sent, письма нет.

3. Тесты

В apps/rooms/tests_freelancer_termination.py, не новый файл. Максимум три метода, роли и статусы через subTest.

1. Сервис: покинуть и опротестовать пишут системные строки в чат кейса; у протеста на кейсе есть текст; короткий протест не меняет статус и не шлёт письмо; письмо содержит текст протеста.
2. HTTP модалка: у фрилансера есть «К списку комнат»; шапка сайта (например «Дашборд» / «Комнаты») доступна в разметке страницы вместе с модалкой — не спрятана оверлеем логикой «контент комнаты».
3. HTTP список комнат: при notice_sent в рабочем списке есть бейдж «Идёт расторжение — нужен ответ» и нет комнаты в архиве; после протеста бейдж «Заблокировано, рассматривается увольнение»; у тимлида на своём списке этих бейджей нет.

Существующие тесты протеста (кнопка без поля) поправить под новую форму, не оставлять красными.

python manage.py test целиком.

4. Что не делать

- Не inbox саппорта и не письмо тимлиду.
- Не писать причину и текст протеста в командную ленту / team-чат.
- Не класть открытый кейс в архив.
- Не крестик на модалке и не клик по фону «закрыл и работаю здесь».
- Не переписывать автомат статусов, слот, архив членства, cron finalize_expired_terminations — только порядок «системное сообщение, потом complete» и поле протеста.
- Не трогать CSS шапки глобально сверх z-index / области оверлея.

5. Приёмка, ручной чеклист

Два окна, Иван в двух комнатах.

1. Тимлид шлёт расторжение в комнате A. Иван в A: модалка, шапка кликается, «К списку комнат» ведёт на «Комнаты». Комната B открывается, работа в B идёт.
2. В списке комната A красная, бейдж «Идёт расторжение — нужен ответ». Клик по бейджу — снова модалка. Комната B без красного.
3. Опротестовать без текста / коротко — ошибка, кейс не уходит в appeal. С текстом ≥20 — письмо в console/outbox с формулировкой, бейдж «Заблокировано, рассматривается увольнение», в чате кейса системная строка и текст протеста. Тимлид видит это в форме расторжения.
4. Повторный сценарий: «Покинуть» — в чате кейса «Фрилансер покинул проект», слот пуст, комната в архиве, красного бейджа в рабочем списке нет.
