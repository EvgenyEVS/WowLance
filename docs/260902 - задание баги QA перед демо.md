## 1. Зачем

Золотой путь доходит до inbox менеджера, но «Открыть» даёт 403: менеджер не член комнаты. Живой мастер после оплаты оставляет комнату без слотов (seed кладёт `quick_start`, мастер — нет). На карточке фрилансера висит «К каталогу» → 403. На шаге 3 мастера две кнопки запуска.

---

## 2. Что сделать

### 2.1. Блокер: менеджер открывает свою Hot-задачу

Сейчас `task_detail` идёт через `_get_project` → `user_can_access_project`. Туда попадают владелец, тимлид, `RoomMember`. Менеджер платформы — нет. Список inbox строится по `assignee=user` и типу `MANAGER_HANDOFF`, ссылка «Открыть» ведёт на карточку в URL комнаты.

Не делать менеджера участником комнаты и не пускать его на Обзор / Команду / чат.

Правило доступа к **задаче**:

```text
можно, если user_can_access_project(user, task.project)
        ИЛИ task.assignee_id == user.id
```

Хелпер рядом с остальным RBAC pipeline/rooms (например `user_can_access_task`). Им пользуются GET карточки и POST исполнителя (`task_start`, сдача отчёта, закрытие своей задачи). Review отчёта по-прежнему только `user_can_manage_team`.

На карточке ссылку на лид показывать только если есть доступ к проекту. Менеджеру — имя лида текстом, без URL в комнату.

Тест (в `apps/pipeline/tests.py`, класс inbox): менеджер GET своей handoff-задачи → 200; фрилансер той же комнаты эту handoff не открывает (403); менеджер GET Обзора той комнаты → 403.

### 2.2. High: после оплаты сразу пакет состава

Архитектурный пресет мастера и пакет ролей (`quick_start` / `linkedin` / …) — разные словари. `handle_project_paid` комнату открывает, состав не кладёт. Seed отдельно вызывает `apply_package_and_sync_slots(..., 'quick_start')`.

В `_after_project_paid` (уже есть, сейчас `return None`): если у проекта **ещё нет** снапшота состава — применить пакет и синхронизировать слоты, тем же `apply_package_and_sync_slots`.

Какой пакет:

| `input_data.architecture` | Пакет |
|---------------------------|--------|
| `linkedin` | `linkedin` |
| всё остальное, включая пустое | `quick_start` |

Не затирать состав, если директор уже сохранил пакет/строки на Обзоре. Повторная оплата (`launched_now` ложь) пакет не применяет. Пустой пул каталога оставляет слот пустым — как сейчас.

Тот же helper вызвать из `launch_project`, если этот путь ещё жив в тестах: иначе debug-запуск снова без слотов.

Тест (в `apps/rooms/tests.py` рядом с оплатой): `handle_project_paid` на черновике без состава → есть активный слот `seller_middle` (quick_start). Повторный вызов число слотов не удваивает.

### 2.3. High: «К каталогу» только тем, кому каталог открыт

`apps/profiles/templates/profiles/detail.html`: ссылка «К каталогу» сейчас у всех, в том числе у владельца карточки-фрилансера.

Показывать её только ролям, которые уже ходят в каталог (директор, тимлид, admin). Фрилансеру и менеджеру — не рендерить. URL `/freelancers/` по-прежнему 403, это не менять.

Тест в `apps/profiles/tests.py`: фрилансер на своей карточке не видит «К каталогу»; директор на чужой карточке видит.

### 2.4. Medium: одна кнопка запуска — оплата-stub

Шаг 3 мастера и карточка черновика сейчас: «Оплатить и запустить» **и** «Запустить комнату / проект». Стейкхолдеру непонятно.

Убрать с UI кнопку бесплатного запуска (`action=launch` в мастере, форма `project_launch` на `project_detail`). Оставить `_payment_stub.html` и «Оставить черновик». View `project_launch` не удалять (тесты/DEBUG), только не показывать кнопку.

### 2.5. Low: у фрилансера список — «Комнаты»

В шапке сайта у фрилансера уже «Комнаты», страница `project_list` озаглавлена «Проекты».

Если `user.role == freelancer`: `{% block title %}` и `<h1>` — «Комнаты». Ссылка «← Проекты» в `_room_header.html` для фрилансера — «← Комнаты». У директора и тимлида слово «Проекты» не менять.

## 4. Приёмка

```text

```

Ручной чеклист:

1. Мастер → оплата-stub → Обзор: есть слот подбора (или пустой слот, если в каталоге никого). Нет второй кнопки «Запустить комнату».
2. Тимлид квалифицирует Hot → менеджер inbox → «Открыть» → 200, можно взять в работу. Обзор этой комнаты у менеджера по-прежнему 403.
3. Фрилансер: своя карточка без «К каталогу»; список комнат с заголовком «Комнаты».
4. Директор: вкладки как были (без «Задачи» / «Команда»).
