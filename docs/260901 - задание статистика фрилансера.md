# Задание: своя статистика фрилансера на Обзоре комнаты

| Поле | Значение |
|------|----------|
| **Дата** | 2026-09-01 |
| **Ветка** | `feature/freelancer-project-stats` от актуального `master` |
| **Модуль** | ROOM: вкладка «Обзор» глазами фрилансера. Кабинет `/` и вкладка «Материалы» — **не** эта задача |
| **Связано** | [отображение по ролям](260831%20-%20отображение%20информации%20по%20ролям.md) §3.2, §4.2; отчёт тимлида уже в `apps/pipeline/teamlead_report.py` |

**Не трогать:** `_room_header.html`, `room_comms*`, `chat.py`, `pipeline/teamlead_report.py`, `teamlead_report.html`, `teamlead_dashboard.html`, `freelancer_dashboard.html`, `room_documents.html`, `_unit_economics_table.html`, каталог, вкладку «Команда».

---

## 1. Зачем

Документ по ролям: на Обзоре фрилансера ядро экрана — **своя статистика на этом проекте**. Не чужая доска, не финансы, не отчёт тимлида за даты.

Сейчас полоса уже есть (`#freelancer-project-stats`), но «Лиды» — одно число. Под ней таблица «Состав команды» с лидами **всех** исполнителей (всего по платформе и на проекте). Это мини-отчёт по команде, а не «мои цифры». У тимлида для этого есть вкладка «Команда» и «Отчёт за период».

Целевой экран (вариант B): готовность → **свои шесть цифр** → вводные → мои задачи → свой SLA, если задача его. Таблицы состава нет.

---

## 2. Как должно выглядеть

Порядок Обзора фрилансера сверху вниз — как сейчас, без таблицы состава:

1. «Готов к работе» (если ещё не ready) — не двигать.
2. **Моя статистика на проекте** — полоса `#freelancer-project-stats`.
3. Вводные проекта.
4. Мои задачи.
5. SLA только если стартовая задача назначена ему.

Полоса, шесть карточек, тот же `.metrics-strip` (три колонки, два ряда — нормально). Подпись над цифрами не обязательна, id полосы не менять.

| Метка на карточке | Чей счёт | Формула |
|-------------------|----------|---------|
| Открытые задачи | свои на **этом** проекте | `Task`: `project` + `assignee=user`, статус ≠ `closed` |
| На проверке | те же задачи | статус `ready_for_review` |
| Cold | свои лиды на **этом** проекте | `Lead`: `project` + `creator=user` + `qualification_status=cold` |
| Warm | то же | `warm` |
| Hot | то же | `hot` |
| Отчёты приняты | свои отчёты по задачам **этого** проекта | `Report`: `author=user`, `task__project=project`, `review_status=approved` |

Нули допустимы. Дат, фильтра «с / по», рейтинга и процента принятых **нет** — это дашборд `/` и карточка профиля.

Метки Cold / Warm / Hot — как в отчёте тимлида, латиницей. Не писать «Холодные». Не добавлять «Передано менеджеру».

Не показывать фрилансеру:

- `#team-composition-overview` / «Закрытые лиды (всего)» / «Закрытые лиды (проект)»;
- чужие задачи, чужие лиды, бюджет, слоты, ленту, конфигуратор — это уже скрыто, не вернуть.

Директор и тимлид: Обзор **не менять**. Их полоса — по-прежнему `project_metrics` (бюджет, Hot проекта, открытые задачи комнаты, слоты). `my_project_stats` у них `None`.

---

## 3. Что не путать с отчётом тимлида

У тимлида отдельная страница `/pipeline/.../teamlead_report/`: период, задачи **всей** команды, SLA, ready / не ready, отказы подбора. Файл `teamlead_report.py` **не импортировать** и не переиспользовать. Зерно другое: у фрилансера снимок **своих** сущностей на одном проекте, без дат.

Не копировать в полосу: создано / просрочено / утверждено-не-закрыто, «Сдано» отчётов, «Передано менеджеру», блок «Команда».

---

## 4. Как сделать

### 4.1. Словарь `freelancer_project_stats`

Файл: `apps/rooms/onboarding.py`, функция уже есть. Заменить ключ `leads` на три:

```python
'leads_cold': ...,
'leads_warm': ...,
'leads_hot': ...,
```

Ключи `open_tasks`, `tasks_in_review`, `reports_approved` оставить. Считать одним queryset лидов с `Count` + `filter=Q(...)`, не тремя полными проходами, если получается коротко.

Не класть хелпер в `director_stats.py` и не в `teamlead_report.py`. `rooms → pipeline` для этих моделей уже есть в `onboarding.py` (ADR-001: метрики осознанно).

### 4.2. Шаблон полосы

`apps/rooms/templates/rooms/room_overview.html`, блок `{% if my_project_stats %}`. Вместо одной карточки «Лиды» — три: Cold / Warm / Hot. Порядок карточек как в таблице §2.

### 4.3. Убрать таблицу состава с Обзора фрилансера

- В `room_overview.html` не включать `_team_composition_overview.html`.
- Во `room_overview` не вызывать `team_composition_lead_rows`, в context не класть `team_composition_rows`.
- Функцию `team_composition_lead_rows` и шаблон `_team_composition_overview.html` **удалить**, если больше нигде не используются (сейчас только Обзор фрилансера). Не оставлять мёртвый код «на всякий случай».

Конфигуратор директора/тимлида (`_unit_economics_table.html`) не трогать.

### 4.4. Что не делать

- Не менять `freelancer_metrics` на дашборде `/` (комнаты · открытые задачи · рейтинг).
- Не открывать фрилансеру вкладку «Команда» «чтобы он видел состав там».
- Не строить отчёт за период.
- Не чинить empty-state Материалов (это другой тикет).
- Не ослаблять Quality Gate и не менять модели.
- Не коммитить, если в промпте сказано не коммитить.

## 5. Приёмка

Тесты править, не размножать. Сюит режет формулировки шаблона; здесь как раз **видимость по роли** — такие проверки оставляем и переписываем.

1. `test_freelancer_overview_is_personal_workspace` — есть полоса и Cold/Warm/Hot/«Отчёты приняты»; **нет** `team-composition-overview`, «Закрытые лиды», заголовка «Состав команды» в этом include. Вводные, мои задачи, нет ленты/экономики — как сейчас.
2. `test_freelancer_does_not_see_finance_metrics` — убрать ожидание таблицы состава; оставить «нет юнит-экономики / конфигуратора / CPL».
3. `test_freelancer_team_composition_shows_names_and_lead_counts` — **удалить** (поведение снято). Вместо него один тест: чужой лид коллеги не увеличивает Cold/Warm/Hot текущего фрилансера; свои три квалификации считаются верно.
4. Директор/тимлид: `my_project_stats is None`, лента и конфигуратор на месте.
5. `python manage.py test apps.rooms.tests_freelancer_overview_ui apps.rooms.tests_functional_roles_ui apps.rooms.tests_issue11_tabs_completion`

Ручной чеклист, один проект, три логина:

- Фрилансер: Обзор = готовность (если нужно) → шесть своих цифр → вводные → мои задачи. Нет таблицы коллег. Вкладки без «Команды».
- Тимлид: Обзор как был (экономика, канбан всех, лента). Отчёт за период с дашборда не сломан.
- Директор: Обзор как был (бюджет, экономика).
