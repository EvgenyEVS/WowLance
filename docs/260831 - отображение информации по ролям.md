## 1. Принцип

Три роли работают в одной комнате, но это **три разных рабочих места**:

| Роль | Вопрос, на который отвечает экран | Чего на экране быть не должно |
|------|-----------------------------------|-------------------------------|
| **Фрилансер** | Что мне сделать сегодня и как отчитаться? | Чужие задачи, каталог коллег, подбор команды, деньги заказчика |
| **Тимлид** | Команда собрана? Задачи идут? Качество в норме? | Личные финансы директора, чужие приватные разговоры |
| **Директор** | Сколько потратил / получил / сэкономил? Проект живой? | Операционка найма, чужие задачи как «доска мастера», общий шум команды |

Это не новое требование. Оно уже есть в источниках, сейчас его нужно **довести до экрана**:

- **Исходное ТЗ, §III:** фрилансер видит свои задачи и свой журнал; директор — сводную аналитику; тимлид — задачи, отчёты, квалификацию. Прямо: *«директор не видит личные чаты фрилансеров, тимлид не видит финансовые данные директора»*.
- **Правки Светланы, задача 5:** *«видеть только те инструменты и данные, которые мне нужны»*. Фрилансер — свои задачи, материалы, чат, видео. Тимлид — все вкладки и управление. Директор — статистика и отчёты.
- **Замечания 27.08.2026:** конкретный список «убрать / оставить» — обязателен для релиза.

Менеджер платформы в этот срез не входит: у него отдельный inbox горячих лидов (`/manager/inbox/`), не комната проекта.

## 2. Глобальная навигация (шапка сайта)

| Пункт шапки | Фрилансер | Тимлид | Директор |
|-------------|:---------:|:------:|:--------:|
| Дашборд | да | да | да |
| Мои комнаты / Проекты | да (только свои комнаты) | да (где он тимлид) | да (свои проекты) |
| Каталог фрилансеров | **нет** (и URL даёт 403) | да — инструмент подбора | да — просмотр пула, не операционный найм |
| Профиль / карточка | да (свой) | нет | нет |
| Мастер запуска | нет | нет | да |
| Горячие лиды (inbox) | нет | нет | нет |

**Каталог** — инструмент BIZ для тех, кто **набирает** команду. Фрилансер в каталог не ходит: его приглашают. Сейчас пункт «Каталог» висит в шапке фрилансера — это убрать.

## 3. Комната проекта: вкладки и блоки

Одинаковые URL комнаты сохраняем (не плодим отдельные «приложения»). Меняется **набор вкладок и состав блоков** внутри.

### 3.1. Вкладки комнаты

| Вкладка | Фрилансер | Тимлид | Директор |
|---------|-----------|--------|----------|
| **Обзор** | Описание проекта + **своя** статистика на этом проекте | Пульт: SLA, вижен (чтение), состав, канбан всех задач, лента | Пульт заказчика: вижен, юнит-экономика, KPI, состав (чтение), лента |
| **Команда** | **нет вкладки** | Полное управление: слоты, инвайт, готовность, замены | Состав и статусы (чтение). Инвайт тимлида — да. Операционный подбор сейлов — нет |
| **Задачи** | Только **свои**. Без формы «Новая задача». Без удаления | Все задачи канбана. Создание, назначение, проверка отчётов | Все задачи канбана, **только чтение**. Не ставит и не удаляет |
| **Лиды** | Только **свои** карточки + создание | Все лиды, квалификация Cold/Warm/Hot | Все лиды, только чтение |
| **Материалы** | Чтение скриптов/шаблонов | Загрузка и чтение | Загрузка и чтение |
| **Коммуникации** | Общий чат комнаты + общее видео команды | Общий канал команды **и** отдельный канал с директором | Общий канал (чтение/участие) **и** отдельный канал с тимлидом |

«Лиды» у фрилансера оставляем: это его рабочий результат (звонок → карточка), а не «чужая воронка». На доске он видит только то, что создал сам. Квалификацию в Hot делает только тимлид.

### 3.2. Блоки вкладки «Обзор» — что видно

| Блок | Фрилансер | Тимлид | Директор |
|------|:---------:|:------:|:--------:|
| Вводные проекта (оффер, УТП, ЦА, критерии Hot) | чтение | чтение | чтение + правка |
| Юнит-экономика (стоимость, часы, бюджет, CPL) | **нет** | чтение | чтение + правка состава до/на этапе staffing |
| Конфигуратор «купленных функций» / слоты подбора | **нет** | да | да |
| SLA стартовой задачи | своя задача, если назначена ему | да | да |
| Лента событий комнаты | урезанная: свои задачи, свои отчёты, материалы | полная | полная (без чужих приватных сообщений) |
| Канбан-превью **всех** задач | **нет** — только «мои задачи» (до 5 карточек) | все | все, без кнопок постановки |
| Список команды + кнопка «Управление командой» | **нет** | да | да (кнопка ведёт на вкладку «Команда») |
| Кнопка «Готов к работе» | да, пока не подтвердил | нет | нет |
| Моя статистика на проекте | **да** (ядро экрана) | нет (у него другой отчёт) | нет (у него финансы на дашборде) |

Замечание 27.08 про «убрать управление командой и список внизу» относится **только к фрилансеру**. У тимлида и директора этот блок остаётся.

### 3.3. Задачи — права, не только видимость

| Действие | Фрилансер | Тимлид | Директор |
|----------|:---------:|:------:|:--------:|
| Видеть канбан всех задач комнаты | нет | **да** | да |
| Видеть только свои задачи | **да** | да (фильтр «мои» — опция, не ограничение) | нет такого режима |
| Создать / назначить задачу | нет | **да** | нет |
| Удалить задачу | нет | да (если появится в UI) | нет |
| Взять в работу / сдать отчёт | свои | нет (не исполнитель) | нет |
| Утвердить / отклонить отчёт | нет | **да** | чтение отчёта |
| Закрыть задачу | после утверждённого отчёта — по текущему Quality Gate | да | нет |

В коде создание уже закрыто флагом `can_manage_team`, а список задач фрилансера уже фильтруется по `assignee`. Дыры: на **Обзоре** превью канбана отдаёт **все** задачи всем ролям; в шапке и empty-state формулировки «поставьте задачу» общие. Это и есть «каша».

Исходное ТЗ давало фрилансеру «ленту заказов / отклик на задачу». Правки Светланы и замечания 27.08 это **снимают для комнаты**: задачи назначает тимлид, фрилансер их выполняет. Ленты чужих заказов внутри проекта нет.

### 3.4. Коммуникации — два контура

| Канал | Кто в нём | Кто его видит в UI | Видео |
|-------|-----------|-------------------|--------|
| **Чат комнаты** | директор, тимлид, фрилансеры проекта | все участники комнаты | общее видео команды: `meet.jit.si/wowlance-room-<uuid>` |
| **Канал директор ↔ тимлид** | только эти двое | **только** директор и тимлид этой комнаты. Фрилансер не видит пункт, не видит историю, не получает ссылку | отдельная ссылка, например `meet.jit.si/wowlance-dt-<project_uuid>`. В общий созвон команды по этой ссылке попасть нельзя, потому что адреса разные |

Сейчас в продукте один общий чат и одна Jitsi-ссылка на всю комнату, с явной подписью «пароля нет, ссылку знает вся команда». Для разговора заказчика с тимлидом этого мало — это как раз замечание 27.08.

Ограничение ADR-001 не ломаем: по-прежнему HTMX-чат и публичный Jitsi без JWT. Изоляция на релизе = **отдельная комната сообщений + отдельный URL встречи + скрытие блока по роли**. Self-hosted Jitsi с паролем — phase 2.

## 4. Дашборды — что на главном экране после входа

### 4.1. Сравнение метрик

| Метрика / блок | Фрилансер | Тимлид | Директор |
|----------------|-----------|--------|----------|
| Комнаты / проекты | число своих комнат | проекты, где он тимлид | свои проекты |
| Задачи | открытые **свои** | «на проверке» по всем своим проектам | не операционные счётчики задач |
| Лиды | не на дашборде (внутри комнаты — свои) | Warm / Hot по проектам | Hot в разрезе своих проектов |
| Рейтинг / журнал | **да**: рейтинг, % принятых отчётов, история проектов | рейтинг исполнителей — внутри комнаты, не на дашборде | нет |
| Деньги проекта (бюджет, CPL) | нет | нет на дашборде (в комнате — чтение экономики) | **да**: сколько потратил |
| Выручка / сделки | нет | нет | **да**: сколько заработал (по закрытым сделкам; пока контур сделок тонкий — честно показывать 0 / «нет данных») |
| Экономия vs классический найм | нет | нет | **да**: оценка сэкономленного времени и денег |
| Отчёт за период | нет | **да — главное новое действие** | своя статистика на дашборде, без «отчёта тимлида» |
| Приватная связь директор ↔ тимлид | нет | вход в канал с директором | вход в канал с тимлидом |
| Каталог / пул | нет | да | вторичная ссылка, не главный CTA |

### 4.2. Фрилансер — целевой кабинет

Экран отвечает: «мои проекты, мои задачи, мой результат».

**Шапка кабинета**

- Приветствие, роль.
- Метрики: комнаты · открытые задачи · рейтинг · % принятых отчётов (по всем проектам).

**Два списка, не три «feature-card» про портфолио**

1. **Мои комнаты** — название проекта, статус, число моих открытых задач, ссылка в обзор комнаты.
2. **Мои задачи** (по всем проектам) — название, проект, статус, дедлайн.

**Доступно внутри комнаты:** описание, свои задачи, материалы, общий чат/видео, своя статистика на этом проекте (задачи закрыто / на проверке, лиды создано, принятые отчёты).

**Не доступно нигде:** каталог фрилансеров, вкладка «Команда», постановка и удаление задач, чужие задачи и чужие лиды, юнит-экономика, список участников с email и кнопкой удаления.

Профиль и портфолио остаются (это BIZ: как его находят), но не являются центром кабинета после того, как он уже в комнате.

### 4.3. Тимлид — целевой кабинет

Экран отвечает: «контроль исполнения». Канбан всех задач **как сейчас** — это норма, его не режем.

**Шапка кабинета**

- Проекты в работе · задач на проверке · Warm/Hot.

**Главное действие (новое, замечание 27.08)**

- Блок **«Отчёт за период»**: поля «с» / «по» → кнопка «Сформировать».
- Результат — страница (и при необходимости печать/HTML) **по выбранному проекту или по всем его проектам**:
  - задачи: создано / в работе / на проверке / закрыто, просрочено;
  - отчёты: сдано / утверждено / отклонено;
  - лиды: Cold / Warm / Hot, передано менеджеру;
  - команда: кто ready, кто нет, замены;
  - SLA: стартовая задача в срок / просрочена.
- Цифры считаются из уже существующих `Task`, `Report`, `Lead`, `RoomMember`. Новых сущностей «Отчёт» в БД не требуется на релизе — достаточно выборки за даты.

**В комнате** — полный канбан, управление командой, квалификация лидов, материалы, два канала связи (общий + с директором).

### 4.4. Директор — целевой кабинет

Экран отвечает: «окупаемость и контроль без операционки».

**Финансовая полоса (новое, замечание 27.08)**

| Показатель | Смысл для заказчика | Откуда на релизе |
|------------|---------------------|------------------|
| **Потратил** | Оплаченный / заложенный бюджет запуска и команды | `Project.budget` по юнит-экономике; если оплаты-заглушки — подпись «по составу команды, тестовая оплата» |
| **Заработал** | Результат сделок с горячих лидов | Сумма закрытых сделок, когда контур Deal появится. До этого: «0 ₽ / контур сделок не в этом релизе», **не** выдуманная цифра |
| **Сэкономил времени** | Против классического найма из ТЗ (5–14 дней отбор + 3–7 онбординг vs 1 час staffing + 24 ч до звонков) | Оценка: дни, которые не ушли на найм. Формула фиксируется в коде и подписывается «оценка платформы», не бухгалтерский факт |
| **Сэкономил денег** | Против штатной команды на том же объёме часов | Оценка: ставка штата × часы состава минус бюджет комнаты. Тоже с подписью «оценка» |

Рядом — уже привычные счётчики: проекты, активные комнаты, горячие лиды. Канбан и подбор **не** дублируются на дашборде: для этого есть комната.

**Связь с тимлидом** — отдельная карточка: «Написать тимлиду» / «Видео с тимлидом» по текущему проекту (если тимлид назначен). Это не тот же созвон, что у сейлов.

Мастер запуска остаётся главным CTA для нового проекта. Каталог — не первый экран директора: команду набирает тимлид по купленным слотам.

## 5. Как сейчас vs как надо

Сводка по репозиторию на 31.08.2026. Нужна команде, чтобы не гадать на созвоне.

| Место | Как сейчас | Как надо |
|-------|------------|----------|
| Шапка фрилансера | Дашборд, Комнаты, Профиль, **Каталог** | Без каталога; `/freelancers/` → 403 |
| Обзор комнаты у фрилансера | Юнит-экономика без денег, канбан **всех** задач, **список команды + «Управление командой»**, лента, SLA | Описание + свои задачи + своя статистика. Без команды, без слотов, без чужого канбана |
| Вкладка «Команда» | Одна на всех; у фрилансера нет слотов, но есть таблица участников и «Готов к работе» | Вкладки нет. «Готов к работе» — на обзоре |
| Задачи | View уже фильтрует assignee для фрилансера; форма создания — у `can_manage_team` (директор **и** тимлид) | Фильтр оставить. Создание — **только тимлид**. Директор и фрилансер форму не видят |
| Обзор: `kanban_preview` | `Task.objects.filter(project=…)[:50]` без роли | Для фрилансера — только его задачи |
| Коммуникации | Один чат + одна Jitsi на всех | Плюс скрытый канал директор↔тимлид и вторая ссылка видео |
| Дашборд фрилансера | Комнаты / открытые задачи / рейтинг + карточки «Профиль, Портфолио, Комнаты» | Журнал: комнаты, задачи, рейтинг, % отчётов, история проектов |
| Дашборд тимлида | 3 цифры + ссылки «Проекты» и «Каталог» | То же + **отчёт за период** |
| Дашборд директора | Проекты / активные комнаты / Hot + мастер + **каталог как равный CTA** | Финансы и экономия на первом плане; каталог вторичен; вход в чат с тимлидом |
| Материалы | Грузить может любой участник | Фрилансер читает; грузят директор и тимлид |
| ТЗ vs правки | ТЗ: фрилансер «берёт задачи из ленты» | Для релиза принимаем правки 17.08 + замечания 27.08: задачи **назначают**, не разбирают с витрины |

Что уже совпадает с целевым и **не ломать**:

- фрилансер не видит чужие карточки задач и чужие лиды по прямому URL (403);
- фрилансер не видит деньги в юнит-экономике и блок подбора слотов (`can_view_unit_economics_finance`, `can_view_composition_staffing`);
- вводные правит только директор-владелец;
- Quality Gate: задача с обязательным отчётом не закрывается без утверждения тимлида;
- канбан тимлида — четыре колонки на всех задачах комнаты.

## 6. Что сделать к созвону (3 дня)

Стейкхолдеры выпускают неидеальный продукт. К созвону важна **чистая картина ролей**, а не Stripe и не JWT-Jitsi.

Приоритет: то, что сейчас выглядит как «все видят одно и то же».

### Обязательно (показ ролей)

1. **Фрилансер, навигация и каталог** — убрать пункт «Каталог»; доступ к `/freelancers/` закрыть.
2. **Фрилансер, обзор** — убрать список команды и кнопку «Управление командой»; убрать превью чужого канбана; не показывать слоты/конфигуратор.
3. **Фрилансер, вкладки** — скрыть «Команда»; «Задачи» без формы создания; тексты empty-state без «поставьте задачу».
4. **Директор, задачи** — убрать форму создания с канбана (создание остаётся у тимлида).
5. **Шапка комнаты** — список вкладок зависит от роли, один `_room_header.html`.

### Желательно (чтобы было что показать по пунктам 2 и 3 замечаний)

6. **Тимлид:** форма «с / по» → HTML-сводка по проекту (задачи, отчёты, лиды). Без PDF.
7. **Директор:** на дашборде четыре показателя (потратил / заработал / время / деньги). «Заработал» может быть нулём с честной подписью.
8. **Канал директор ↔ тимлид:** отдельный тред в коммуникациях + отдельная Jitsi-ссылка, блок скрыт от фрилансера. Если не успеваем рабочий тред — хотя бы видимый блок «скоро / отдельная встреча» с **другой** ссылкой Jitsi, чтобы на созвоне было что открыть двум ролям.

### Не брать в эти 3 дня

- Боевой Stripe, кошелёк, формула рейтинга, self-hosted Jitsi с паролем.
- Микросервисы, отдельный фронт.
- Полноценная воронка Deal «как в большом ТЗ» — только честный ноль на дашборде директора.

### Разделение по исполнителям

| Кто | Тикеты | Почему так |
|-----|--------|------------|
| Разработчик 1 + сильный ИИ | Вкладки и обзор по роли; 403 на каталог; превью канбана; канал директор↔тимлид (модель сообщений или отдельный `RoomChatMessage.channel`) | Затрагивает RBAC, шапку комнаты, чат |
| Разработчик 2 + простой ИИ | Шапка сайта без каталога у фрилансера; тексты empty-state; дашборд фрилансера (списки своих задач/комнат); форма отчёта тимлида как выборка + шаблон; карточки метрик директора по уже известным полям | Повторение существующих шаблонов дашборда, без новой статусной машины |

Приёмка к созвону — три логина демо (`director@` / `teamlead@` / фрилансер из seed) и чеклист: **на одном и том же проекте три разных экрана, без каталога у фрилансера, без «управления командой» у фрилансера, канбан всех задач у тимлида на месте.**

## 7. Краткая формулировка для созвона

> Комната одна, рабочие места разные. Фрилансер видит себя: задачи, материалы, описание, общий чат, свою статистику. Тимлид видит всю доску и собирает отчёт за даты. Директор видит деньги, экономию и отдельный разговор с тимлидом — без операционного шума команды.
