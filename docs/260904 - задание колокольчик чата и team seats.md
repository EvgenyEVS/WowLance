## Часть A. Колокольчик уведомлений о чате

### A.1. Зачем

Сообщение видно, только если пользователь уже на вкладке «Коммуникации». На дашборде, в каталоге, на задачах переписка молчит. Для демо и для работы нужна **глобальная** точка: колокольчик в шапке сайта на любой странице.

### A.2. Где стоит

`templates/base.html`, `.header-left`, **между** чипом «Мастер запуска» / кнопкой заработка фрилансера и блоком `.nav-menu`. Не внутри логотипа, не справа от «Выйти».

Только для **залогиненного** пользователя, у которого есть хотя бы один доступный чат (директор / тимлид / фрилансер-член комнаты). Менеджер платформы и гость — колокольчика нет.

### A.3. Как выглядит

Активная кнопка-ссылка (не `span`, не `disabled`): иконка колокольчика (SVG или unicode 🔔 — один вариант на весь продукт) + бейдж с числом.

| Состояние | Бейдж | Клик |
|-----------|-------|------|
| Нет непрочитанных разговоров | бейджа нет (или не показывать «0») | всё равно кликабельно — см. A.5 |
| Непрочитано в **одном** чате | `1` | сразу на этот чат |
| Непрочитано в **двух** (и более) чатах | `2` (не сумма сообщений) | панель со списком этих чатов; каждый пункт — переход |

**Число на колокольчике = число разговоров с непрочитанным, не число сообщений.**

Разговор = пара `(комната, канал)`:

- командный чат проекта A;
- чат директор↔тимлид того же проекта A — это **второй** разговор;
- командный чат проекта B — третий.

Два непрочитанных в одном командном чате → бейдж всё равно **1**. Сообщения из команды и из DT → бейдж **2**.

Свои сообщения непрочитанными не считаются и тост не показывают.

Фрилансер **никогда** не видит DT в бейдже, тосте и списке (как на вкладке Коммуникации).

### A.4. Всплывающее уведомление (тост)

Пока пользователь на **любой** странице с `base.html` (дашборд, проекты, каталог, задачи, профиль…):

1. Колокольчик опрашивает сервер с тем же ритмом, что лента чата: `every 7s`, только если вкладка браузера видима (`document.visibilityState === 'visible'`). Сокеты, SSE, Web Push, Django Channels — **не** делать (ADR-001).
2. Если с прошлого опроса появилось новое чужое сообщение в доступном канале — возле колокольчика всплывает тост: автор, имя проекта, превью текста (~80 символов), канал («Команда» или «С тимлидом» / «С директором»).
3. Тост кликабелен — тот же URL, что у пункта списка (A.5). Сам скрывается через ~5 с или по клику на крестик.
4. Несколько новых разговоров за один опрос — **несколько тостов** (стопка у колокольчика), не один «у вас 2 чата» без имён.
5. Если пользователь **уже** на странице этого чата (вкладка Коммуникации, этот `project_id`, этот канал в кадре) — тост по этому каналу **не** показывать: он и так видит ленту. Бейдж для этого канала тоже считать прочитанным (A.6).

Не дублировать Django `messages` (зелёные алерты под шапкой) — отдельный слой у колокольчика.

### A.5. Куда ведёт клик

URL уже есть:

| Разговор | Куда |
|----------|------|
| Команда | `{% url 'rooms:room_comms' project.id %}` (якорь командного блока, если есть id вроде `#comms-team`) |
| Директор↔тимлид | `{% url 'rooms:room_comms' project.id %}#comms-dt-chat` — как кнопки в `_room_header.html` |

- **Один** непрочитанный разговор → `href` колокольчика сразу туда, без промежуточной страницы.
- **Два и больше** → клик открывает выпадающий список под колокольчиком (не отдельный URL «инбокс»). В списке **все** непрочитанные разговоры: название проекта + тип канала. Клик по строке → тот же переход, список закрыть.
- **Ноль** непрочитанных → переход в командный чат **последней** доступной комнаты (по последнему сообщению, которое пользователь имеет право видеть; если сообщений не было — в `room_comms` любой своей комнаты). Не на `#`, не на `javascript:void`.

`room_comms_teamlead.html` для колокольчика не использовать: канон — `room_comms` + якорь DT.

### A.6. Что считать непрочитанным

Сейчас у `RoomChatMessage` нет курсора прочтения. Нужна модель, например `ChatReadCursor`:

| Поле | Зачем |
|------|--------|
| `user` | чей курсор |
| `room` | какая комната |
| `channel` | `team` или `director_teamlead` |
| `last_read_at` | сообщения с `created_at > last_read_at` и `author ≠ user` — непрочитанные |

Unique вместе `(user, room, channel)`.

**Прочитано**, когда пользователь открыл этот канал: GET `room_comms` отмечает `team`; если в запросе якорь DT / пользователь видит DT-блок — отметить и `director_teamlead` для owner/тимлида. Не ждать отдельной кнопки «прочитано».

Первый курсор: при первом показе колокольчика **не** засыпать тостами всей историей. Вариант: создать курсор с `last_read_at=now()`, чтобы непрочитанными стали только сообщения **после** внедрения. Старые треды не вспыхивают на демо в день выкладки.

Хелпер рядом с чатом: `apps/rooms/chat.py` или тонкий `apps/rooms/chat_notifications.py`. RBAC не дублировать: список комнат/каналов брать из уже существующих `user_can_access_project` и `user_can_access_director_teamlead_comms`.

Poll-endpoint, например `GET /chat-alerts/` (`rooms:chat_alerts`), `login_required`, отдаёт HTML-фрагмент колокольчика+тостов (как `_chat_messages.html` для HTMX), не JSON-SPA.

В `base.html`: обёртка с `hx-get`, `hx-trigger="every 7s [document.visibilityState === 'visible']"`, `hx-swap="outerHTML"` по корню колокольчика. Первый HTML — обычный SSR при загрузке страницы, чтобы до первого poll уже был бейдж.

### A.7. Как сделать

1. Модель + миграция + admin (по желанию, для отладки демо).
2. Сервис: непрочитанные разговоры, последнее чужое сообщение для тоста, mark-read.
3. View poll + вызов mark-read из `room_comms`.
4. Partial `_header_chat_bell.html`, include в `base.html`.
5. CSS: `.header-bell`, бейдж, тост `position` у колокольчика, z-index выше контента, не перекрывать «Выйти» на узкой ширине — перенос в `.header-left` как у чипа.

Не менять интервал опроса ленты на Коммуникациях (7 с). Не писать `RoomActivity` на каждое сообщение (как сейчас).

### A.8. Что не делать (часть A)

- Не WebSocket / Channels / внешний Firebase.
- Не уведомления о задачах, лидах, отчётах — только чат.
- Не показывать фрилансеру чужой DT даже в токене URL (ссылку не строить).
- Не считать бейдж как `COUNT(messages)`.
- Не ломать XSS-экранирование текста в тосте: как в `_chat_messages.html`, без `|safe`.

### A.9. Приёмка части A

Новый файл, например `apps/rooms/tests_chat_alerts.py`:

1. Фрилансер: чужое сообщение в team → бейдж 1; своё → бейдж не растёт. DT-сообщение в той же комнате на бейдж фрилансера не влияет.
2. Тимлид: непрочитанное team + непрочитанное DT одной комнаты → бейдж **2**. GET `room_comms` сбрасывает team; после визита с `#comms-dt-chat` (или открытия страницы, где DT в DOM) сбрасывается и DT.
3. Две комнаты, по одному непрочитанному team → бейдж 2; в фрагменте poll две строки/два тоста, две разные ссылки.
4. Менеджер GET любая страница: колокольчика нет.
5. Гость: нет.
6. Текст тоста экранируется (`<script>` как текст).
7. `python manage.py test apps.rooms.tests_chat_alerts apps.rooms.tests_room_chat`

Ручной чеклист, два браузера:

- Директор на дашборде, тимлид пишет в DT → через ≤7 с тост у колокольчика, бейдж 1, клик → `#comms-dt-chat`.
- Не выходя с дашборда, фрилансер пишет в команду → бейдж 2, два тоста; клик по колокольчику — список из двух чатов.
- Фрилансер на «Задачи»: тост только по команде, DT нет.
- Открыли чат — бейдж погас, повтор того же сообщения тостом не всплывает.

## Часть B. Подпись мест в команде (не «Слоты»)

### B.1. Зачем

Слово «слот» для англоязычной аудитории — календарь или казино. В продукте это **купленные места**: одно место — один исполнитель.

Зафиксированная подпись метрики (демо / EN, так и вшить в шаблон):

**`Team seats: {filled} of {total} filled`**

Пример: `Team seats: 2 of 4 filled`.

`filled` / `total` — как сейчас `project_metrics.slots_filled` и `slots_total` (человек назначен / мест куплено). Это **не** «ready to start». Человек на месте, но без «Готов к работе», всё равно входит в `filled`.

Запрещено в этой метрике: `slots`, `working`, `roles`.

### B.2. Где менять

Только пользовательская метрика на **Обзоре** директора и тимлида:

```71:72:apps/rooms/templates/rooms/room_overview.html
            <span class="metric-label">Слоты</span>
            <strong class="metric-value">{{ project_metrics.slots_filled }}/{{ project_metrics.slots_total }}</strong>
```

Сделать **одну** строку (лейбл можно оставить коротким, значение — полная фраза; или вся фраза в `.metric-value`):

```django
<span class="metric-label">Team seats</span>
<strong class="metric-value">{{ project_metrics.slots_filled }} of {{ project_metrics.slots_total }} filled</strong>
```

Итог на экране читается как **Team seats: 2 of 4 filled** (двоеточие в CSS/`::after` у лейбла или пробел — как удобнее, смысл фразы не ломать).

Если `slots_total == 0`: `Team seats: none yet`, не `0 of 0 filled`.

Карточки слотов на вкладке «Команда», статусы «Свободен» / «Готов к работе», конфигуратор, модели, `director_stats` ключи `slots_filled` — **не** переименовывать. Меняется только эта метрика Обзора.

Фрилансер эту полосу не видит (`project_metrics` у него `None`) — не добавлять.

### B.3. Тесты части B

Расширить обзорный UI-тест директора/тимлида (например `tests_freelancer_overview_ui` / `tests_issue11_tabs_completion`):

- есть `Team seats` и `of` + `filled`;
- нет отдельной карточки с подписью ровно `Слоты` как единственный лейбл этой метрики;
- при 2 filled и 4 total в HTML есть `2 of 4 filled`.

`python manage.py test apps.rooms.tests_freelancer_overview_ui apps.rooms.tests_issue11_tabs_completion`
