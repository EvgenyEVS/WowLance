---

## 1. Зачем

Фрилансеру на демо нужно всё время видеть **свой** заработок и открыть **историю начислений**. Сейчас ни журнала, ни суммы нет: бюджет комнаты — деньги директора за слот, `earned_total` на дашборде директора — про сделки, кошелёк в MVP_SCOPE сознательно phase 2.

Не подставлять `Project.budget` и не `FunctionalRoleConfig.monthly_cost`. Это чужие деньги.

Две кнопки — не бейджи. Всегда `<a href="...">`, даже если сумма 0. Клик ведёт на историю, не на `#` и не на `javascript:void`.

---

## 2. Как должно выглядеть

Точные подписи (слово «долларов» не склонять в этой задаче):

| Где | Текст | Куда ведёт клик |
|-----|--------|-----------------|
| Шапка сайта, **сразу справа от** логотипа «WowLance» | `Я заработал всего {N} долларов на WowLance` | общая история: все начисления пользователя |
| Шапка комнаты, **в одном ряду с** `{{ project.name }}` (`.page-header` уже `display:flex; justify-content:space-between`) | `Я заработал {N} долларов на этом проекте` | история **этого** проекта |

`{N}` — целое неотрицательное число (0, 10, 20…). Без `$`, без `₽`, без «USD» в подписи: валюта уже словом «долларов».

Кто видит:

| Роль | Кнопка у логотипа | Кнопка у названия проекта |
|------|:-----------------:|:-------------------------:|
| Фрилансер (залогинен) | **всегда** на любой странице с `base.html` | на **любой** вкладке комнаты, куда он имеет доступ |
| Директор, тимлид, менеджер, гость | нет | нет |

«Всегда» = пока фрилансер в сессии (дашборд, список комнат, профиль, Обзор, Задачи, Лиды, Материалы, Коммуникации, история начислений). На `/login/` кнопки нет — пользователя ещё нет.

Внешний вид: ссылка-кнопка (`btn btn-secondary btn-sm` или узкий класс рядом с `.header-chip`). Не `disabled`, не `pointer-events: none`. На узком экране можно переносить на вторую строку — не обрезать текст.

## 3. История начислений

Две URL, один шаблон списка:

| Имя | Путь | Содержимое |
|-----|------|------------|
| `pipeline:freelancer_accruals` | `/earnings/` | все начисления текущего фрилансера, новые сверху |
| `pipeline:freelancer_project_accruals` | `/projects/<uuid>/room/earnings/` | только этот проект; страница **комнаты** — подключить `_room_header.html`, вкладки как обычно |

Колонки таблицы: дата, проект (на общей — ссылка в обзор комнаты; на проектной можно не дублировать), основание (название задачи / отчёта), сумма в долларах.

Пустой список: «Начислений пока нет.» Без призыва «вывести на карту». Под таблицей одна строка-пояснение: это журнал начислений, не кошелёк и не выплата.

Доступ:

- только роль `freelancer`;
- общая история — свои строки;
- проектная — ещё и доступ в комнату (`_get_accessible_project` / членство), иначе 403;
- директор/тимлид/чужой фрилансер — 403, даже зная URL.

На проектной истории видны **обе** кнопки (шапка сайта + шапка комнаты). На `/earnings/` — только кнопка у логотипа.

## 4. Откуда цифра

Источник **только** журнал. Кнопка у логотипа = `SUM(amount)` по пользователю. Кнопка у проекта = `SUM` по пользователю **и** этому `project_id`. Нет строк → 0, кнопки всё равно активны.

### 4.1. Модель

Новая модель в `apps.pipeline` (это результат работы, не каталог BIZ), например `FreelancerAccrual`:

| Поле | Зачем |
|------|--------|
| `id` | UUID, как у Task/Report |
| `freelancer` | FK на User, кому начислили |
| `project` | FK на `rooms.Project` |
| `report` | FK на `Report`, `unique=True`, `null=True` — идемпотентность |
| `amount` | `Decimal`, доллары, ≥ 0 |
| `title` | короткая строка в историю, например «Отчёт принят: …» |
| `created_at` | сортировка |

`related_name` не пересекать с существующими. Зарегистрировать в `apps/pipeline/admin.py`, чтобы на демо можно было дописать строку руками.

### 4.2. Когда появляется строка

В `apps.pipeline.services.review_report`, ветка `approve=True`, **в той же транзакции**: если у отчёта ещё нет начисления — создать на `report.author` (он же исполнитель) и `task.project`.

Сумма — **заглушка**, именованная константа рядом с сервисом, например:

```python
DEMO_ACCRUAL_USD_PER_APPROVED_REPORT = Decimal('10')
```

Не брать ставку из юнит-экономики (там рубли директора). Не писать строку при отклонении. Повторный approve сервис уже запрещает — на всякий случай `get_or_create` по `report`.

Это не кошелёк и не Stripe. Когда появится боевая выплата, константу заменят; UI кнопок и журнал остаются.

### 4.3. Как отдать сумму в шаблоны

**Логотип (все страницы).** Context processor, лениво, по образцу `apps.rooms.context_processors.add_to_room`: считать SUM только если `user.role == freelancer`, иначе не ходить в БД. Подключить в `wowlance/settings.py` рядом с уже существующим processor. Не класть это в `apps.profiles` (BIZ не импортирует pipeline).

**Название проекта (все вкладки комнаты).** Добавить в `room_nav_context` ключ, например `freelancer_project_earned` (`Decimal` или `None`). Считать SUM только для фрилансера-члена комнаты. Все view комнаты (`rooms` и `pipeline`) уже делают `**room_nav_context(...)` — новые URL задач/лидов/чата не забывать: если какой-то view шапки не получает словарь, кнопка не появится.

Хелпер сумм — файл вроде `apps/pipeline/accruals.py`, не в `director_stats.py` и не в `teamlead_report.py`.

## 5. Как сделать

### 5.1. Шапка сайта

`templates/base.html`, блок `.header-left`: после `</a>` логотипа, до чипа «Мастер запуска».

```django
{% if user.is_authenticated and user.role == 'freelancer' %}
<a href="{% url 'pipeline:freelancer_accruals' %}" class="btn btn-secondary btn-sm header-earned-link">
    Я заработал всего {{ freelancer_earned_total }} долларов на WowLance
</a>
{% endif %}
```

Целое в шаблоне: `{{ freelancer_earned_total|floatformat:0 }}` либо уже `int` из процессора.

Чуть CSS: в `.header-left` ссылка не должна разъезжать логотип; на узкой ширине `flex-wrap` у `.header-inner` уже есть.

### 5.2. Шапка комнаты

`apps/rooms/templates/rooms/_room_header.html`: второй ребёнок `.page-header` справа от блока с h1. Только при `user.role == 'freelancer'` и когда сумма в context не `None`.

```django
{% if user.role == 'freelancer' and freelancer_project_earned != None %}
<a href="{% url 'pipeline:freelancer_project_accruals' project.id %}"
   class="btn btn-secondary btn-sm header-earned-link">
    Я заработал {{ freelancer_project_earned|floatformat:0 }} долларов на этом проекте
</a>
{% endif %}
```

Кнопки «Коммуникация с тимлидом/директором» **не переносить** и не прятать.

### 5.3. View истории

Два тонких view в `apps/pipeline/views.py`. Queryset только `freelancer=request.user`. Проектный view: проект доступен + роль фрилансер. `select_related('project', 'report', 'report__task')`.

### 5.4. Что не делать

- Не показывать кнопки тимлиду «для прозрачности».
- Не считать N из числа лидов, часов или бюджета комнаты.
- Не делать вывод на карту, баланс к выводу, Stripe.
- Не менять Quality Gate задач, кроме вызова начисления из уже существующего `review_report`.
- Не импортировать pipeline из `apps.profiles`.
- Не коммитить, если в промпте сказано не коммитить.

## 6. Приёмка

Новый файл тестов, например `apps/pipeline/tests_freelancer_accruals.py`. Не размазывать по `tests_room_chat`.

1. Фрилансер GET дашборд `/` и GET Обзор комнаты: есть обе формулировки кнопок, это `<a href=...>`, href общей → `/earnings/`, href проектной → `.../room/earnings/`. Суммы 0, если журнал пуст.
2. Директор и тимлид на Обзоре той же комнаты: **нет** подстрок «Я заработал всего» и «на этом проекте».
3. Фрилансер GET `/earnings/` → 200. Тимлид/директор → 403.
4. Фрилансер GET проектной истории своей комнаты → 200, шапка комнаты на месте. Чужой проект / не член → 403.
5. `review_report(approve=True)` создаёт одну строку на 10 USD; кнопка у проекта = 10, кнопка у логотипа = 10. Второй проект с ещё одним принятым отчётом: логотип 20, в первом проекте по-прежнему 10.
6. Отклонение отчёта строк не создаёт. Повторно на тот же `report_id` вторую строку не писать.
7. `python manage.py test apps.pipeline.tests_freelancer_accruals apps.pipeline.tests apps.rooms.tests_issue11_tabs_completion`

Ручной чеклист, один фрилансер:

- Логин → справа от WowLance кнопка с 0, клик → пустая история.
- Зайти в комнату (любая вкладка: Обзор, Задачи, Материалы, Коммуникации) → справа от названия проекта кнопка с 0, клик → пустая история проекта, вкладки на месте.
- Тимлид принимает отчёт → обе кнопки показывают 10; в историях есть строка.
- Логин директором: у логотипа и у названия проекта кнопок заработка нет.
