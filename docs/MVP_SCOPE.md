## MVP (первый демо-релиз) — делаем

Критерий готовности MVP: на демо проходит сквозной сценарий  
**фрилансер с видео в каталоге → директор «оплатил» → комната staffing → тимлид пригласил → фрилансер подтвердил → задача/отчёт → Hot-лид у менеджера**.

| № | Что видит пользователь | Зачем |
|---|------------------------|--------|
| 1 | Обязательная **видеопрезентация** в профиле; без видео нельзя стать «доступен» / попасть в выдачу каталога (по правилам MVP) | Ключевое требование правок |
| 2 | Каталог: фильтр «только с видео», карточка с видео и базовой статистикой | Подбор команды |
| 3 | Регистрация фрилансера + поток **`?ref=` из WOW Talent`** с автозаполнением | Два входа в биржу |
| 4 | Модерация профиля (ожидает / одобрен) — в каталоге только подходящие | Качество базы |
| 5 | **Оплата запуска** в интерфейсе (тестовая/заглушка) → сразу комната со статусом «набор команды» | Тот же UX, что после оплаты |
| 6 | Назначение/работа тимлида, **приглашение** фрилансера → подтверждение → доступ в комнату | Staffing |
| 7 | Вкладки комнаты: **Обзор, Задачи, Лиды, Материалы** | Ядро ROOM |
| 8 | Задачи, отчёты со скрином, Cold/Warm/Hot, Hot → менеджер | Основной бизнес-процесс |
| 9 | Вкладка **Видео**: кнопка/ссылка на видеовстречу комнаты (Jitsi) | Есть в 6 вкладках, упрощённо |
| 10 | Базовые права ролей (директор / тимлид / фрилансер / менеджер) | Безопасность сценария |

## Phase 2 — сознательно позже

| № | Что | Почему не в MVP |
|---|-----|-----------------|
| 1 | Полноценный **чат** в реальном времени (переписка как в мессенджере) | Долго; в MVP достаточно заглушки или простого обновления списка сообщений |
| 2 | «Боевой» **Stripe** / реальные деньги, возвраты, подписка | Нужны юр./биллинг-контур; UX оплаты уже закрываем stub’ом |
| 3 | Реальный API **WOW Talent** (не демо-подстановка) | Зависит от внешнего партнёра |
| 4 | **Кошелёк** и реальные выплаты фрилансеру | После стабильного контура задач/отчётов |
| 5 | Автоподбор «топ-3» команды | Nice-to-have |
| 6 | Жёсткие **SLA-таймеры** (4ч / 24ч) с автозаменами | После базового invite/задач |
| 7 | Богатый UX видеозвонка (как полноценный Meet внутри UI) | Ссылка на встречу достаточна для старта |
| 8 | Полная воронка **сделок (Deal)** менеджера «как в большом ТЗ» | Hot-inbox в MVP важнее |
| 9 | Отдельные **микросервисы** / разный деплой BIZ и ROOM | Согласовано: одна платформа; вынос — при росте |

*В phase 2 на экране комнаты допустима вкладка «Чат» с текстом «скоро» — это не срыв MVP.*
