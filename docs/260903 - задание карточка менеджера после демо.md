---

1. Зачем

Вчера закрыли блокер: менеджер открывает свою задачу передачи Hot (200) и берёт в работу. Карточка при этом всё ещё выглядит как комната: вкладки Обзор / Лиды / Материалы / Коммуникации и «← К задачам». Клик ведёт в 403. На показе обходили («вкладки не трогать»). После показа оболочка должна совпасть с правом: задача — да, комната — нет.

---

2. Что сделать

2.1. High: нет доступа к проекту — нет навигации комнаты

Страница задачи для менеджера сейчас та же оболочка, что у тимлида.

Правило:

- Навигация комнаты (Обзор, Лиды, Материалы, Коммуникации) и «← К задачам» — только если уже есть доступ к проекту (тот же смысл, что user_can_access_project).
- Флаг в context view (например show_room_chrome). Не ветвить шаблон по имени роли.
- Без доступа к проекту: нет вкладок комнаты, название проекта не ведёт на Обзор.
- Назад для менеджера: список inbox, текст «← Горячие лиды» (как пункт «Горячие лиды» в шапке сайта).

Не добавлять менеджера в комнату. Не расширять user_can_access_project. Обзор, Команда и чат по-прежнему 403.

Не выключать вкладки комнаты на всех страницах «на всякий случай». Навигация комнаты остаётся у тех, кто в комнате. На карточке менеджера её просто нет.

Тест: расширить test_manager_opens_own_handoff_but_not_room_overview в apps/pipeline/tests.py (тот же класс inbox, subTest).

- менеджер GET своей задачи передачи → 200;
- нет ссылки на Обзор этой комнаты и нет «← К задачам»;
- есть переход в inbox («Горячие лиды»);
- GET Обзора → 403;
- фрилансер той же комнаты эту задачу не открывает (403) — как сейчас;
- тимлид или директор на своей задаче по-прежнему видит навигацию комнаты и «← К задачам».

Новый файл тестов не заводить.

2.2. Medium: квалификация лида — отказ 403, не вспышка

Сейчас POST квалификации пускает любого, кто видит проект (фрилансер — член комнаты). Сервис бросает PermissionDenied, view ловит и отвечает редиректом со вспышкой: HTTP 200. Формы у фрилансера нет, Hot не ставится, но ответ лживый.

В lead_qualify не глотать PermissionDenied. Ошибки данных (ValidationError) по-прежнему вспышкой. Фрилансер POST квалификации → 403. Тимлид по-прежнему редирект и смена статуса.

Тест в том же apps/pipeline/tests.py: фрилансер POST квалификации → 403, статус лида не меняется. Один HTTP, роли через subTest. Золотой путь тимлида не ломать.

4. Приёмка

python manage.py test

Ручной чеклист:

1. Тимлид ставит Hot → менеджер inbox → «Открыть» → карточка без вкладок комнаты, «← Горячие лиды» ведёт в inbox, «Взять в работу» работает.
2. Прямой адрес Обзора этой комнаты у менеджера — 403.
3. Тимлид открывает обычную задачу исполнителя — навигация комнаты и «← К задачам» на месте.
4. Фрилансер POST квалификации (если дернуть адрес) — 403, лид не Hot.
