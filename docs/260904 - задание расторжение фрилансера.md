# Задание: расторжение с фрилансером (причина, срок, чат, архив)

| Поле | Значение |
|------|----------|
| **Дата** | 2026-09-04 |
| **Ветка** | `feature/freelancer-termination` от актуального `master` |
| **Модуль** | ROOM: вкладка «Команда», членство, доступ к работе в комнате |
| **Связано** | `room_remove_member`, `RoomMember`, `user_can_access_project`; ADR-001 (чат без сокетов) |

**Не трогать:** «Другой сейлер» / `replace_slot_member` (это замена на слоте, не расторжение), канал директор↔тимлид, каталог, юнит-экономику, отчёт тимлида за период, начисления (кроме того что строки **не удалять**), Jitsi.

Сейчас «Удалить» в `_room_members.html` — `confirm('Удалить участника?')` и сразу `member.delete()`. Для **фрилансера** этот путь заменить. Удаление **тимлида** из таблицы — **не** эта задача (кнопка может остаться как есть).

---

## 1. Зачем

Тимлид не выкидывает человека одним кликом в браузерном confirm. Расторжение — письменная причина, уведомление, три дня на ответ, отдельный чат и сохранение статистики. Фрилансер либо уходит сам, либо оспаривает; молчание = уход автоматически.

---

## 2. Сценарий целиком

```text
Тимлид: Удалить
  → не confirm, а форма (причина обязательна)
  → «Отправить фрилансеру уведомление о расторжении»
  → кейс notice_sent, слот ещё занят, работа фрилансера заблокирована
  → у фрилансера по центру экрана модалка на ЛЮБОЙ вкладке этой комнаты
  → чат расторжения (только этот тимлид и этот фрилансер)

Фрилансер в течение 3 суток:
  «Покинуть проект»     → архив (см. §5), слот свободен
  «Опротестовать решение» → письмо в техподдержку, статус appeal_pending,
                           работать нельзя, пока нет решения
  ничего                 → на исходе 3 суток то же, что «Покинуть»

Тимлид: «Отозвать увольнение» пока кейс не завершён (notice_sent или appeal_pending,
         пока саппорт не утвердил расторжение) → модалка снимается, работа снова можно.
```

Пока кейс открыт (`notice_sent` или `appeal_pending`), фрилансер **не продолжает работу** в проекте: не стартует задачи, не сдаёт отчёты, не создаёт лиды, не пишет в **командный** чат. Может: видеть комнату, модалку, чат расторжения, две кнопки (пока `notice_sent`), ждать саппорт (`appeal_pending`).

---

## 3. Форма тимлида (вместо confirm)

Место: вкладка «Команда», кнопка «Удалить» только у `role_in_room == freelancer`.

Клик открывает **форму на странице или модалку в UI**, не `window.confirm` и не `onsubmit="return confirm(...)"`.

Поля:

| Поле | Правило |
|------|---------|
| Причина | `textarea`, обязательно, минимум 20 символов (чтобы не «ок») |
| Кнопка | точная подпись: **«Отправить фрилансеру уведомление о расторжении»** |

После отправки на этой же форме (тимлид может открыть её снова со строки участника или с баннера «идёт расторжение»):

- текст причины (только чтение);
- дедлайн «ответ до …» (initiated_at + 3 суток);
- кнопка **«Отозвать увольнение»**;
- **чат расторжения** (поле ввода + лента). Не командный чат и не DT.

Повторно открыть форму, пока кейс открыт: не создавать второй кейс на ту же пару комната+фрилансер.

`room_remove_member` для фрилансера больше не удаляет строку сразу. POST без причины — 400/ошибка формы, не молчаливый delete.

---

## 4. Модалка фрилансера

На **любой** вкладке этой комнаты (Обзор, Задачи, Лиды, Материалы, Коммуникации), по центру экрана, пока кейс `notice_sent`. Не прятать крестиком «закрыл и работаю». Фон затемнён, контент комнаты не кликается.

Содержание: имя проекта, причина тимлида, срок (осталось / дата), чат расторжения (тот же тред, что у тимлида).

Кнопки (только `notice_sent`):

1. **Покинуть проект**
2. **Опротестовать решение**

На `appeal_pending`: те же причина и чат, кнопки убрать, текст: «Ожидается решение техподдержки. Работать в проекте нельзя.»

Подключать модалку из `_room_header.html` (он на всех вкладках) **или** из `base.html` по флагу в context, если фрилансер в комнате с открытым кейсом. Не копировать разметку в каждый шаблон вкладки.

---

## 5. «Покинуть» и авто-истечение: архив, не вырезать историю

**Запрещено:** `CASCADE`-удаление задач, лидов, отчётов, начислений, сообщений командного чата. `RoomMember.delete()` для этого фрилансера **не** вызывать.

Завершение расторжения (`leave` / таймаут / саппорт утвердил):

1. Членство не уничтожать. Статус членства, например `archived` / `left` (новое поле на `RoomMember` **или** только статус на кейсе + `left_at` на member). Unique `(room, user)` сохранить одну строку.
2. Отвязать `function_slot` (`NULL`) — место в команде снова пустое, тимлид может подобрать другого.
3. Открытые задачи этого assignee: не удалять. Снять с работы: статус вернуть в `new` и `assignee` оставить для истории **или** оставить assignee, но `user_can_access_task` / start/report для него запрещены. Предпочтительно: задачи **не** переназначать молча другому человеку; слот свободен, тимлид ставит заново. Закрытые задачи, лиды `creator=user`, принятые отчёты, `FreelancerAccrual` — без изменений.
4. В ленте комнаты событие (можно расширить `MEMBER_REMOVED` текстом «расторжение: …», причину в ленту целиком не обязательно).
5. Фрилансер **не** видит операционные вкладки как член команды. Комната попадает в **архив**: список «Архивные комнаты» на его дашборде или в «Комнаты» — название, статус расторгнут, ссылка на **read-only** обзор (вводные + свои прошлые цифры `my_project_stats` / начисления по проекту). Без постановки задач, без «Готов к работе», без командного чата, без модалки расторжения (кейс закрыт).

Пока кейс только `notice_sent` / `appeal_pending`, в списке комнат комната **ещё не архив** — он заходит и видит модалку.

Повторно взять того же человека в эту комнату позже: реактивировать ту же `RoomMember` (статус снова freelancer active), не вторую строку.

---

## 6. «Опротестовать»

- Письмо на техподдержку: `SUPPORT_EMAIL` в settings (по умолчанию например `support@wowlance.com`), тема/тело: проект, фрилансер, тимлид, причина, ссылка в админку. На демо `EMAIL_BACKEND` console/locmem — как активация; в тестах `mail.outbox`.
- Кейс → `appeal_pending`. Таймер 3 суток **останавливается** (авто-уход не срабатывает, пока нет решения).
- Работать нельзя, как в §2.
- Решения саппорта в продукте **нет входящего ящика**. MVP: действия в **Django admin** у кейса: «Оставить в силе» (= завершить как покинуть) и «Отклонить расторжение» (= как отозвать). Без admin-кнопок демо не закрыть спор.

---

## 7. Срок 3 дня и авто-уход

Константа, например `TERMINATION_NOTICE_DAYS = 3`. `deadline = initiated_at + 3 days`.

Срабатывать в двух местах (не только cron):

1. Лениво: любой заход в комнату / poll модалки, если `now >= deadline` и статус `notice_sent` → завершить как «Покинуть».
2. Команда `python manage.py finalize_expired_terminations` — для VPS по cron раз в час. В задании описать, в systemd не обязательно править.

`appeal_pending` по этому таймеру **не** закрывать.

---

## 8. Отозвать (тимлид)

Пока кейс `notice_sent` или `appeal_pending` (и саппорт ещё не утвердил): POST «Отозвать увольнение». Статус `revoked`, модалка исчезает, блок работы снимается, слот и членство как до уведомления. В чат расторжения можно оставить системную строку «увольнение отозвано» или просто закрыть тред для новых сообщений.

После архива отозвать нельзя.

---

## 9. Чат расторжения

Отдельные сообщения, FK на кейс (не `RoomChatMessage.channel=team`). Участники: `initiated_by` (тимлид) и фрилансер. Директор и другие фрилансеры **не** читают.

Лента в форме тимлида и в модалке фрилансера. HTMX poll как командный чат (`every 7s`, видимая вкладка), без WebSocket. Текст экранировать, без `|safe`. Лимит длины как у комнатного чата (2000).

## 10. Модель (ориентир)

`FreelancerTermination` (имя на ваш вкус) в `apps.rooms`:

| Поле | Смысл |
|------|--------|
| room, freelancer (User), member | кто и где |
| initiated_by | тимлид |
| reason | текст причины |
| status | `notice_sent` / `appeal_pending` / `completed` / `revoked` |
| initiated_at, deadline_at | часы 3 суток |
| completed_at, revoked_at | |
| unique открытый кейс | один незакрытый (`notice_sent`\|`appeal_pending`) на `(room, freelancer)` |

Плюс `TerminationMessage`: case, author, text, created_at.

На `RoomMember` — явное «ещё в работе / в архиве», если статус нельзя надёжно вывести только из кейса. `user_can_access_project` для архива: доступ **read-only** к обзору/цифрам, не к write-операциям. Сейчас доступ = «есть RoomMember»; после доработки различать active vs archived.

Блокировка работы: в `start_task`, `submit_report`, `create_lead`, `post_chat_message` (только team), `confirm_freelancer_readiness` — если открытый кейс на этом user+room → `PermissionDenied` с понятным текстом.

## 11. Что не делать

- Не `window.confirm` на удаление фрилансера.
- Не удалять статистику «чтобы слот был чистый».
- Не показывать модалку на дашборде `/` и в чужих комнатах.
- Не слать протест в командный чат вместо письма.
- Не заводить полноценный inbox саппорта и не Stripe.
- Не менять удаление директора (и так запрещено) и сценарий замены слота, кроме конфликта unique member — замена слота по-прежнему `delete()` текущей записи; **не смешивать** с открытым кейсом расторжения: если кейс открыт, «Удалить» и «Другой сейлер» для этого человека недоступны (кнопки скрыть / 400).

## 12. Приёмка

Новый файл `apps/rooms/tests_freelancer_termination.py`. Не ломать `tests_room_chat` изоляцию каналов.

1. POST «Удалить» без причины / короткая причина — member на месте, кейса нет.
2. Валидная форма → кейс `notice_sent`, `confirm(` в HTML команды нет у фрилансера, есть «Отправить фрилансеру уведомление о расторжении».
3. Фрилансер GET Обзор, Задачи, Материалы: в теле модалка, причина, две кнопки. Тимлид ту модалку не видит.
4. `start_task` / создание лида во время `notice_sent` → 403; чат расторжения POST 200.
5. «Покинуть» → member archived, слот пуст, Task/Lead/Report/Accrual на месте, фрилансер не в операционном списке команды, комната в архиве.
6. «Опротестовать» → письмо в `mail.outbox` на SUPPORT_EMAIL, статус `appeal_pending`, авто-уход на deadline не срабатывает, работать нельзя.
7. freeze_time / сдвиг `deadline_at` в прошлое + заход на комнату или management command → как «Покинуть».
8. «Отозвать» на `notice_sent` → модалки нет, задача стартуется снова.
9. Второй открытый кейс на того же member → не создаётся.
10. XSS: причина и сообщение чата как текст.
11. `python manage.py test apps.rooms.tests_freelancer_termination apps.rooms.tests_room_chat apps.pipeline.tests`

Ручной чеклист, два окна:

- Тимлид → Команда → Удалить Ивана → форма с причиной → отправить.
- Иван на Лидах этой комнаты: модалка по центру, не закрывается мимо кнопок; пишет в чат — тимлид видит в форме.
- Иван «Опротестовать» — работать нельзя; тимлид отзывает — модалка пропала, Иван берёт задачу.
- Повтор: отправить → Иван «Покинуть» → слот пуст, цифры Ивана на архивной комнате видны, задач/лидов в БД не исчезло.
