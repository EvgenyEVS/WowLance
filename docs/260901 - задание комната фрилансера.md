## 1. Зачем

Вкладки у фрилансера уже правильные: нет «Команды», свои задачи, 403 на каталог. Две поверхности комнаты всё ещё чужие.

**Обзор.** Чужой пульт: таблица состава с производительностью и Hot leads/мес, баннер SLA «когда все исполнители подтвердят», полная лента событий комнаты.

**Материалы.** Список файлов по роли **не режется** — это правильно, фрилансер должен видеть те же файлы, что и тимлид. Ломается **пустая папка**: empty-state написан для загрузчика («Загрузите презентацию… как в Dropbox»), а `can_upload` у фрилансера `False` (`user_can_manage_team` — только тимлид проекта). Кнопки и формы нет, призыв загрузить остаётся. Для исполнителя это выглядит как «документы не отображаются». Тот же текст видит и директор: он тоже не может загружать — не открывать ему загрузку в этой задаче, только поправить copy по флагу `can_upload`.

Целевой Обзор фрилансера (документ §3.2): **вводные + свои задачи + своя статистика на этом проекте**. Без состава, слотов, чужого канбана, денег, операционного SLA.

Целевые Материалы фрилансера: те же файлы, что у команды; пустая папка — текст для **читателя**, не для загрузчика.

## 2. Как должно выглядеть

### 2.1. Обзор у фрилансера

Порядок сверху вниз:

1. **«Готов к работе»** — если членство фрилансера ещё не `ready` (сейчас кнопка внизу — поднять сюда, это его главное действие).
2. **Моя статистика на проекте** — новая полоса метрик (только свои цифры).
3. **Вводные проекта** — как сейчас, только чтение (оффер, УТП, ЦА, Hot, KPI).
4. **Мои задачи** — как сейчас: до 5 своих карточек, ссылка «Все задачи» на вкладку.
5. **SLA** — только если стартовая задача **назначена ему**. Иначе блока нет (ни idle «команда подтвердит», ни чужой дедлайн).

Не показывать фрилансеру:

- конфигуратор / «Состав команды» / производительность / Hot leads/мес (`_unit_economics_table.html` не подключать);
- блок «Подбор команды» (уже скрыт флагом — не вернуть);
- управленческие метрики (бюджет, слоты, чужие открытые задачи) — `project_metrics` для него уже `None`, так и оставить;
- ленту событий комнаты (там подбор, удаления, чужие задачи);
- «Назначить тимлида».

Директор и тимлид: Обзор **не менять по составу блоков**. Конфигуратор, лента, SLA idle, канбан всех задач, метрики бюджета — как сейчас.

### 2.2. Материалы у фрилансера

Если в комнате **есть файлы** — те же карточки, что у тимлида: название, ссылка, кто загрузил, дата. Queryset `room.documents` не фильтровать по роли. Кнопку «Удалить» фрилансеру не показывать (уже так: только `can_manage_team` или свой файл).

Если папка **пуста**:

| Кто | Что видит |
|-----|-----------|
| Тимлид (`can_upload`) | Как сейчас: «Папка пуста» + «Загрузите презентацию, скрипт звонка или бриф — как в Dropbox комнаты.» + кнопка «Загрузить файл» и форма ниже |
| Фрилансер и директор (не `can_upload`) | Заголовок «Папка пуста» **оставить**. Абзац заменить: материалы загружает тимлид проекта; когда файлы появятся, они будут на этой вкладке. **Без** «Загрузите…», **без** «как в Dropbox», **без** кнопки и якоря `#upload` |

Форму загрузки не открывать фрилансеру и директору. `can_upload` / `room_document_upload` не менять.

Клики по `/media/...` на демо с `DJANGO_DEBUG=0` — **не эта задача** (nginx). Если карточка есть, а файл 404 — это инфра, не RBAC и не шаблон empty-state.

## 3. Как сделать

### 3.1. Не подключать конфигуратор фрилансеру

В `apps/rooms/templates/rooms/room_overview.html` обернуть include:

```django
{% if can_view_unit_economics_finance %}
<div class="fr-configurator-slot" style="margin-top: 16px;">
    {% include 'rooms/_unit_economics_table.html' %}
</div>
{% endif %}
```

Файл `_unit_economics_table.html` не редактировать. Флаг уже `False` у фрилансера (`unit_economics.user_can_view_unit_economics_finance`).

Сломается тест `test_freelancer_does_not_see_finance_metrics` в `apps/rooms/tests_functional_roles_ui.py`: он **сейчас требует** «Состав команды», производительность и Hot leads/мес. Его нужно **переписать**: фрилансер не видит конфигуратор вообще (`assertNotContains` «Состав команды», `functional-roles-configurator`, «Производительность», «Hot leads / мес»). Проверки «нет стоимости / CPL / Подбор команды» оставить. Тимлид/директор по-прежнему видят экономику (`test_teamlead_still_sees_finance_metrics` не ломать).

### 3.2. SLA только на свою стартовую задачу

Во `room_overview` для роли фрилансер:

- если `start_calls_task` есть **и** `start_calls_task.assignee_id == request.user.id` — баннер как сейчас;
- иначе в шаблон не передавать задачу / idle не рендерить.

Для директора и тимлида поведение SLA не менять (включая idle).

Скрипт обратного отсчёта в `extra_js` уже завязан на `start_calls_task` — после фильтра у фрилансера без своей задачи таймера не будет.

### 3.3. Лента событий

Фрилансеру блок «Лента событий» на Обзоре не показывать. Не фильтровать типы событий в этой задаче — проще скрыть целиком, чем утечёт «слот заменён». Остальным ролям лента без изменений.

### 3.4. Моя статистика на проекте

Новый словарь context, например `my_project_stats`, **только** если `request.user.role == freelancer` (член комнаты и так есть). Считать из существующих моделей, без новых таблиц:

| Метка | Откуда |
|-------|--------|
| Открытые задачи | `Task` этого проекта, `assignee=user`, статус ≠ closed |
| На проверке | те же, статус `ready_for_review` (как на дашборде тимлида) |
| Лиды | `Lead` этого проекта, `creator=user` |
| Отчёты приняты | `Report` по задачам проекта, `author=user`, `review_status=approved` |

Хелпер — рядом с обзором, не в `director_stats.py`. Например функция в `apps/rooms/onboarding.py` или небольшой блок в `room_overview`. Шаблон: тот же `.metrics-strip`, id например `freelancer-project-stats`. Пустые нули допустимы.

На дашборд `/` это **не** выносить.

### 3.5. Кнопка «Готов к работе»

Ту же форму, что внизу страницы, показать **сверху** (после шапки / перед статистикой). Дубликат внизу убрать, чтобы не было двух кнопок.

### 3.6. Материалы: empty-state для читателя, не для загрузчика

Файл: `apps/rooms/templates/rooms/room_documents.html`. View `room_documents` **не** менять: `can_upload` уже `user_can_manage_team`, queryset уже полный.

В `{% empty %}` ветке `{% for group in material_groups %}`:

- заголовок «Папка пуста» общий (его ждёт `apps/core/tests_product_path.py` → `test_documents_dropbox_empty_state`);
- абзац и кнопка — от `can_upload`.

Пример:

```django
{% empty %}
<div class="empty-state">
    <h3>Папка пуста</h3>
    {% if can_upload %}
    <p>Загрузите презентацию, скрипт звонка или бриф — как в Dropbox комнаты.</p>
    <a href="#upload" class="btn btn-primary" onclick="document.getElementById('upload').scrollIntoView({behavior:'smooth'}); return false;">Загрузить файл</a>
    {% else %}
    <p>Скрипты, бриф и презентации загружает тимлид проекта. Когда файлы появятся, они будут на этой вкладке.</p>
    {% endif %}
</div>
{% endfor %}
```

Форма `#upload` ниже по файлу уже под `{% if can_upload %}` — не трогать.

Не делать в этой задаче:

- не открывать загрузку фрилансеру или директору;
- не фильтровать `room.documents` «чтобы фрилансер не видел чужое» — он **должен** видеть общие материалы;
- не чинить раздачу media (`wowlance/urls.py` `static(MEDIA_URL)` только при `DEBUG`, nginx на VPS).

Тесты (добавить в `apps/rooms/tests_room_tabs.py`, класс `RoomMaterialsTabTests`):

1. Фрилансер, папка пуста: 200, есть «Папка пуста», есть фраза про тимлида, **нет** «Загрузите презентацию», **нет** «Загрузить файл», **нет** `enctype="multipart/form-data"`.
2. Тимлид, папка пуста: по-прежнему «Загрузите презентацию» и форма загрузки.
3. Фрилансер, в комнате уже есть файл (создать `RoomDocument` как в `test_existing_documents_are_listed_with_author_and_date`): видит title файла. Empty-state нет.

`test_ui_label_is_materials_not_documents` не ломать: в новом абзаце не должно быть подстроки «Документ».

### 3.7. Что не делать

- Не менять `_room_header.html`, `room_comms*`, `chat.py`, модели чата, URLs коммуникаций.
- Не открывать фрилансеру вкладку «Команда» и каталог.
- Не показывать ему бюджет «для прозрачности».
- Не строить новый дашборд фрилансера в этой задаче.
- Не ослаблять Quality Gate задач.
- Не менять `can_upload` / `room_document_upload` / queryset документов.
- Не настраивать nginx и не раздавать media при `DEBUG=False`.
- Не коммитить, если в промпте сказано не коммитить.

## 4. Приёмка

Тесты (расширить `apps/rooms/tests_freelancer_overview_ui.py` + `apps/rooms/tests_room_tabs.py` + поправить `tests_functional_roles_ui.py`):

1. Фрилансер GET Обзор: нет «Состав команды», нет `functional-roles-configurator`, нет «Юнит-экономика», нет «Подбор команды», нет «Лента событий».
2. Есть «Вводные проекта», «Мои задачи», полоса своей статистики.
3. Нет idle-текста «SLA запустится после готовности команды».
4. Если стартовая задача назначена другому — баннера SLA нет; если ему — баннер есть.
5. Директор/тимлид: конфигуратор, лента, idle SLA на месте.
6. Фрилансер GET Материалы, пусто: читательский empty-state, нет призыва загрузить и нет формы. Тимлид в той же пустой папке — старый Dropbox-текст и форма. Фрилансер при наличии файла видит title.
7. `python manage.py test apps.rooms.tests_freelancer_overview_ui apps.rooms.tests_functional_roles_ui apps.rooms.tests_issue11_tabs_completion apps.rooms.tests_room_tabs apps.core.tests_product_path`

Ручной чеклист, один проект, три логина:

- Фрилансер: Обзор = готовность (если нужно) → цифры про себя → вводные → мои задачи. Нет состава и ленты. Вкладки: Обзор, Задачи, Лиды, Материалы, Коммуникации. Коммуникации — только команда. Материалы без файлов — текст про тимлида, не «загрузите». После загрузки тимлидом — карточка файла видна фрилансеру.
- Тимлид: Обзор как был (экономика, канбан всех, лента). Материалы пустые — «Загрузите…» и форма.
- Директор: Обзор как был (бюджет, экономика, инвайт тимлида). Материалы пустые — тот же читательский текст, что у фрилансера (загрузка по-прежнему только у тимлида).
